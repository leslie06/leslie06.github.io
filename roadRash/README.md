# 暴力摩托 · ROAD RASH

街头摩托竞速，但规矩只有一条：**谁先到谁拿钱**。八条街、七个对手、来往车流、路障、护栏、油污、暴雨，后面几条街还有警察和悬赏头目。你可以踹他们、抢他们的棍子铁链双节棍撬棍，也可以被他们打下车 —— 那就徒步跑回去，重新骑上。四档难度，从「新手」到要解锁的「亡命」。

单文件、零依赖、零外部请求：画面是 Canvas 现画的 —— 摩托、车手、车辆全是矢量路径每帧现描，楼和街景是开局程序化生成的贴图；音乐和音效由 Web Audio 实时合成。仓库里没有任何图片或音频素材。

画布按**设备像素**跑满（1080p 上就是 1920×1080，最高 1080 行），干净扁平 + 深色描边的画风。

| `↑` / `W` | 油门 |
| `↓` / `S` | 刹车 |
| `←` `→` | 变向（速度越高转得越迟钝） |
| `A` / `J` / `Z` | 打左边 |
| `D` / `K` / `X` | 打右边 |

### 手机

横屏竖屏都能玩。**油门是自动的**，两根拇指各管一摊：

| | |
| --- | --- |
| **左手** | 左下一个圆形摇杆。按住圆的哪一侧就往哪边转，手指左右推就能换向，不用抬手；推到半径的六成就是满舵，中间一小段是比例区可以微调。拇指落在圆外稍远的地方，摇杆会挪到拇指底下、从回中开始推，所以左下一大块按哪儿都算数 |
| **右手** | `◀踹` `踹▶` 两个大键在最下面，上面是 `氮气` 和 `刹车`。按住刹车才松油门 |
| **右上角** | 暂停键：继续、重跑本场、静音、回车行。切出去接电话、锁屏时自动暂停 |

原来油门要一直按着：右踹得松油门、左踹得松方向。拿机器人模拟"出脚时松开对应的键 0.2 秒"，第一条街的平均名次从 1.0 掉到 3.5 —— 手机上两根拇指永远在抢键。

按键的位置也是量出来的：**够得着踹的对手画在屏宽约 29%~39% 和 61%~71% 的位置**，原来的方向键和刹车键正好压在他们身上。现在摇杆和它的触控区收在左边 27% 以内，右手一簇收在右边 25% 以内。

摇杆原来是一条横着的细滑块，只有六十来像素高，拇指很容易压到上下沿外面去按空。改成圆以后高度翻了一倍，再加上"落在圆外就把摇杆挪过来"，基本不会按空。

竖屏原来是一条 16:9 的窄条，只占屏幕高度四分之一。现在画面拉到比正方形略高：画布仍按 16:9 渲染，CSS 放大后左右各裁掉一截，投影一行不用改，贴身的对手也还在画面里。矮屏幕（横屏手机）下车行改两列、结算表收紧，"上路"按钮不再被挤出面板。

## 打人

**贴上去才够得着。** 攻击只打你按的那一侧，而且有距离：

| 武器 | 够多远 | 一下多疼 | 出手间隔 |
| --- | --- | --- | --- |
| 徒手（一脚踹出去） | 近 | 14 | 0.32s |
| 木棍 | 中 | 24 | 0.42s |
| 铁链 | 远 | 32 | 0.50s |
| 双节棍 | 中近 | 17 | **0.24s** —— 最快，但一下顶不开人。打断蓄力最顺手 |
| 撬棍 | 中近 | **38** | 0.58s —— 最疼、僵直最久、**把人顶出去最远**（`shove` 0.30，其余 0.17） |

**武器抢来的，不是捡来的。** 有的对手一上路就带着家伙 —— 越往后的街带得越多，前两条街只有棍子和铁链，第三条街起有双节棍，第五条街起有撬棍。**把他打下车，东西就掉在路上**，你骑过去压一下就是你的。你自己被打下车，手里的也会掉。

打人不只是掉血：**挨打的会横向失衡**。把人往外一顶，他很可能自己贴上路灯、撞进对向车道 —— 这比一下一下磨他快得多，也好看得多。

**有护墙的街（盘山公路、暴雨高架），把人顶到墙上额外掉 16 血**（`WALL_SLAM`），僵直拉到 0.6 秒，冒一个「撞墙！」，多充 8 点氮气。反过来你被人从里侧踹到墙上也一样疼 —— 窄路上别让人把你挤在墙边打。

**对手会喊话。** 超过你的时候、把你打下车的时候、被你打下车的时候，头顶冒一句（七个人各有两句口头禅，外加谁都能喊的几句）。平时隔几秒才喊一次，打下车那一下不等。

**对手出手有前摇。** 他先抬手、收腿蓄一下，头顶冒红色感叹号，还有一声吸气（身后看不见的，在你车边另冒一个）。蓄力 0.36~0.46 秒，越往后的街越短。这段时间你有两个选择：

- **闪开。** 他蓄力时基本不追着你打方向，横着让出他的出手距离，他就打空。
- **先下手。** 蓄力中挨一脚会被**打断**：伤害 ×1.5、僵直更久、充一截氮气。

原来对手出脚那一帧就扣血，看得见也没用，只能比手速。但也不能让"狂按踹人"变成无敌，所以有两道保护：

| | |
| --- | --- |
| **僵直保护** `GUARD_T` 0.9s | 僵直过一次之后，这段时间里再挨打只掉血，不僵直、几乎不被顶开。不然每 0.32 秒一脚、每脚僵直 0.34 秒，对手连蓄力都开始不了，还会被一脚一脚顶出他自己的出手距离 |
| **打断保护** `ARMOR_T` 1.6s | 被打断过一次之后，这段时间里蓄力打不断，感叹号外面多一圈黄 —— 这一下只能躲 |

单挑量过：对着一个血无限的对手狂按 20 秒，他蓄力 14 次、被打断 9 次、仍然打中你 5 次。

**拿家伙的人站得远。** 棍子、铁链的够得比脚远，他们会停在你脚够不着、自己够得着的地方出手。想打断他就得先凑近，或者自己也抢一根。

**看得见谁要打你。** 身边的对手头顶有名字、血条和手里的家伙；距离条下面有一面后视镜，身后五千单位以内的人都是一个点，正在蓄力的点外面套红圈。初代 Road Rash 的仪表盘上就有后视镜，原来这里没有，挨的打有四分之一以上来自看不见的身后。

## 摔了怎么办

血打光、迎头撞车、追尾、撞路障、冲出赛道太远 —— 都会**被甩出车外**。

慢速蹭上红白路障（车速不到极速的 35%）不会摔，只是被顶住、掉一截血。

然后是这游戏最要命的一段：**车会继续往前滑一段停下，你得跑过去重新骑上。** 这中间名次一路往下掉，对手一个个从你身边过去。跑回去大约要三秒，重新上车时血只回到四成半。

一场里摔两次基本就没前三了。所以真正的问题从来不是"能不能打赢"，是"值不值得为了打这一下冒摔车的险"。

## 路上还有什么

| | |
| --- | --- |
| **对向车道** | 全程最危险的东西。迎头撞上必摔，没有例外。喇叭声由远及近，听见就该变道了 |
| **同向车流** | 撞上会被顶住、掉速掉血，蹭一下就得往外让 |
| **路障 / 锥筒** | 锥筒只是掉速，红白路障高速撞上直接摔。**对手也会撞**，所以也会躲，看多远取决于他的技术 —— 原来对手直接从栏杆里穿过去。工业区的路障从每公里 10 个减到 5.4 个，原来顶速下不到两秒一个 |
| **落石** | 盘山公路上的路障：高速撞上直接摔，比红白路障还疼一点 |
| **油污 / 积水** | 集装箱港的油污、暴雨高架的积水。**压上去不摔，但会打滑**：方向只剩四成，车自己往压上去那一刻的方向横着溜（油污 0.8 秒，积水 0.55 秒）。油污、积水不会被撞掉，谁压上去谁滑 —— 对手也一样 |
| **护墙** | 盘山公路两侧是波形护栏，暴雨高架两侧是混凝土防撞墙。**冲不出路**，但贴上去那一下掉血掉速，贴着蹭一直掉 |
| **雨天路滑** | 暴雨高架整条街抓地 ×0.86：转向、刹车都打折，过弯被甩得更狠。天上隔几秒打一次闪电，雷声晚一点才到 |
| **跳台与颠簸** | 冲过坡顶会腾空，空中几乎转不了向，落地掉一点速。工业区、旧城区、港口的铁轨颠得最狠 |
| **隧道** | 市中心、工业区、夜战、盘山公路、暴雨高架各有一段，里面只剩路灯 |
| **弯道牌 / 龙门架** | 盘山公路的急弯外侧立着黄底黑箭头，箭头指弯往哪边拐；暴雨高架隔一段有一架横跨路面的绿色路牌 |

对手不是背景板：他们也躲车流、也会撞车翻掉、也会互相别。你在后视里看见的每一次翻车都是真的算出来的。

## 氮气

原来冒险没有任何回报：擦着来车过去、贴着对手的尾流、把人踹下车，都不会让你更快。车速完全由车决定。现在这些都往氮气槽里充：

| 怎么充 | 充多少 |
| --- | --- |
| 撂倒一个人 | +30 |
| 打断一次蓄力 | +12（普通命中 +4） |
| 贴着来车擦过去 | +16（同向车 +10）。车速要过极速的 55%，离车身不到 `NEAR_BAND` 才算，真蹭上不算 |
| 贴在对手正后方的尾流里 | 每秒 +16，要贴满 0.35 秒才开始 |

槽满 100，一格 33。放一格烧 1.3 秒，推力很猛，能冲到车极速的 122%；烧完之后慢慢回落，不是一下被掐回去。开局送一格，让人一上来就知道有这东西。放氮气时两根排气口喷蓝焰、画面边缘泛蓝、速度线变色，引擎声开滤波器。

氮气是让战斗和竞速互相喂养的那一环：打得好 → 有氮气 → 追得上前面的人 → 又贴得上人打。警察的车只比你快 2%，一格氮气就能甩开他一下。

**橡皮筋也跟着改了。** 原来落后的对手无条件 ×1.14 追你，骑得好也拉不开，攒的氮气冲出去几秒就被拉回来。现在只在你摔车后的 12 秒里（`CATCH_T`）才给他们大追赶，平时只有 ×1.03。领先太多的对手照旧收一点速度，免得你摔一次就再也看不见人。

## 警察

**工业区、夜战、集装箱港、暴雨高架有警察。** 跑过四成路程（暴雨高架是 28%）、或者摔够三次，警笛就响了。

他从后面追上来，贴住你的时候屏幕顶上那条会红蓝交替闪。**被贴住四秒就是被捕，这一场作废**（新手 6 秒，疯子 3.2 秒，亡命 2.6 秒）。但他不是无解的：

- 连续变线能甩开他一下 —— 他横向跟得比你慢一点点
- **抡他。** 打翻了他要四秒半才能爬起来，那时候你已经跑没影了
- 他自己也会撞上对向来车

### 悬赏头目

第五场的 **★刀疤**（撬棍）和最后一场的 **★阎王**（铁链）占掉发车最前面的位置。血是同场对手的 1.9 / 2.3 倍，车比同场所有人都快（×1.03 / ×1.05），出手更凶。头顶名牌是金色的，后视镜里的点套一圈金边。**亲手把他打下车**才给赏金：刀疤 $400、阎王 $1000，再乘难度的奖金倍率，算进这一场的进项。

**前三名才能进下一条街**（新手前四，亡命前二）。一场的进项有四笔，合起来再乘难度的奖金倍率：

| | | |
| --- | --- | --- |
| **完赛费** | 过线就有，跟名次无关 | 第一场 $380，第五场 $900，第八场 $1400 |
| **名次奖** | 只发前七，头名是尾名的十几倍 | 第一场 $1500 / 950 / 600 / 180 / 120 / 80 / 40，第八场头名 $8200 |
| **撂倒** | 每放倒一个人 | $90 |
| **悬赏** | 亲手撂倒头目 | $400 / $1000 |

完赛费这一档是补进去的，原来没有。原来前四之外一分钱不发，于是第一场跑砸就等于出局 —— 没钱换车，换不了车就永远进不了前四，后面每一场都是 $0。八个随机种子里有三个的机器人就是这么从头垫底到尾的。那不是难，是死角。现在垫底也能拿完赛费，跑三场就换得起第二台车：**输了只是慢，不是断。** 测试里钉了一条 `每一场完赛都有钱拿`。

## 难度

新游戏先选难度，**车行里随时能换**（最佳成绩按难度分开记）。「老手」就是原来那套数值，一个字没动，其余三档围着它伸缩：

| | 新手 | 老手 | 疯子 | 亡命 |
| --- | --- | --- | --- | --- |
| 对手极速 | ×0.94 | ×1 | ×1.035 | ×1.065 |
| 出手意愿 / 血量 | ×0.6 / ×0.8 | ×1 | ×1.35 / ×1.2 | ×1.7 / ×1.4 |
| 蓄力时长 | ×1.3 | ×1 | ×0.85 | ×0.74（最短 0.26s） |
| 带家伙的概率 / 躲车走线 | ×0.6 / ×0.85 | ×1 | ×1.4 / ×1.12 | ×1.8 / ×1.2 |
| 车流 | ×0.8 | ×1 | ×1.15 | ×1.3 |
| 警察比你快 / 贴住几秒被捕 | 0.98 / 6s | 1.02 / 4s | 1.04 / 3.2s | 1.06 / 2.6s |
| 你摔车后落后的对手追多狠 | ×1.07 | ×1.14 | ×1.16 | ×1.18 |
| 重新上车回几成血 | 60% | 45% | 40% | 35% |
| **过关** | 前四 | 前三 | 前三 | **前二** |
| **奖金** | ×0.8 | ×1 | ×1.3 | ×1.6 |

**亡命要解锁**：在疯子（或更难）下跑完全部八条街。中途换到过更低的难度不算 —— 生涯里记着跑过的最低一档（`careerMin`）。

**难度给的额外车速从第一场的 0 爬到第四场才给满。** 不这么做的话，亡命第一场七个对手里有五个比白送的街车快 —— 头一场谁都没得选车，那是车速墙，不是难度。

同一个机器人、同样的车，新手和亡命各跑一遍八条街（九个随机种子）：

| | 平均名次 | 过关场数（按各档自己的过关线） |
| --- | --- | --- |
| 新手 | 1.8 ~ 3.6 | 5 ~ 7 / 8 |
| 亡命 | 3.6 ~ 6.5 | 1 ~ 4 / 8 |

中间两档跟相邻档挨得近，机器人几场的成绩分不出先后（同一条街它能从第一跑到第八）；四档数值一档比一档狠，由台架直接钉住。

## 车行

| 车 | 价 | 极速 | 加速 | 操控 |
| --- | --- | --- | --- | --- |
| 街车 250 | 白送 | 160 | 0.82 | 1.06 |
| 仿赛 600 | $1200 | 187 | 1.00 | 0.96 |
| 公升 1000 | $3600 | 215 | 1.18 | 0.87 |
| 改装怪物 | $9000 | 243 | 1.42 | 0.79 |
| 超跑 1300 | $20000 | 267 | 1.62 | 0.74 |

**车越快越难拐。** 对手的车速是按"这一场你该骑什么车"配的 —— 拿着起步车硬闯第三条街，跑不赢。所以奖金基本都得砸在车上。超跑是给后三条街和高难度准备的：老手场场第一，最后一场前买得起；疯子、亡命奖金倍率高，第七场前后就能换。

原来这个"该骑的车"配错了：对手极速是一条直线涨上去的，跟车行的价格台阶对不上。**就算场场第一、钱全砸在车上，第三场的仿赛和第五场的公升也比一半以上的对手慢。** 现在对手的基准极速按街单独给（`RIVAL_TOP`），公升和仿赛降了价，第二、三名的奖金提了一截：

| 按什么进度打 | 每场比你车快的对手 |
| --- | --- |
| 场场第一 / 场场第二 | 每场 0 个 |
| 场场第三 | 第四场骑着仿赛有 6 个，要多跑一两场攒钱换公升；其余每场最多 2 个 |

台架里钉了一条：场场进前二的进度下，比你车快的对手每场不超过 2 个（疯子、亡命不超过 3 个 —— 对手本来就该更快，奖金倍率是拿来追的，不是拿来抹平的）。八条街、四档难度每一格都量。后三条街的对手极速（12700 / 13400 / 13900）按「场场第二」的进度配：第六场前刚好换得起改装怪物。

## 画面是怎么出来的

**伪 3D，不是真 3D。** 跟初代 Road Rash、OutRun 一个路子：赛道是一串路段，每段只有两个数 —— `curve`（弯多急）和 `y`（高多少）。

```js
// 每一段的两端投影到屏幕上
p.scale = camDepth / (p.z - camZ);
p.sx = W/2 + p.scale * p.cx * W/2;
p.sy = H/2 - p.scale * p.cy * H/2;
p.sw =       p.scale * ROAD_W * W/2;
```

弯道不靠矩阵，靠累加：`x += dx; dx += seg.curve`。所以整条路的碰撞、AI、名次全都退化成**一维 z + 横向偏移 x** 的计算 —— 干净到 AI 可以只关心"前面多远有台车、左右让哪边"。

### 路面：合并成路带，一次填一条

由近及远走一遍，把**连续可见、同色带、同雾档**的若干段并成一条"路带"，用一条路径填出来；遇到坡顶遮挡或者任一项切换就收一段、开新的一段。`ribbon()` 沿着两条边描一圈闭合，路缘石、车道虚线都是同一套。

这么做有两个好处：调用数从逐行 `fillRect` 的一千多次降到几十次，而且**弯道边沿是抗锯齿的**，不再是硬台阶。

**远处不再画明暗交替。** 一条明暗带占 `RUMBLE_LEN` 段；它在屏幕上不到 `MERGE_PX` 高的时候，交替就不再是花纹而是噪声 —— 顶速下每秒二十几条带子扫过去，整条路看着在抖。窄到这个程度之后一律换成两者的中间色（`Road.LUT` 的第 3 档），顺带把远处几百段并进同一条路径。虚线车道在那一段也画成连续两条细线：虚线本来就分辨不出来了，而那两条收敛线是弯道方向最直接的提示。

量出来的效果（`node tools/shot.js --jitter`，清空街景和演员，钉在顶速，量相邻帧的逐像素变化）：

| | 平均帧间差 | 峰值 |
| --- | --- | --- |
| 改前 | 1.89 / 3.30 | 4.76 / 12.99 |
| 改后 | **0.51 / 2.11** | **2.53 / 8.15** |

（两个数分别是市中心和工业区，0~255，越小越稳。）

同一支探针还量了绘制量：视距从 340 段拉到 560 段，但市中心的路径数从 354 降到 146，落点数从 1875 降到 1499 —— **段数多了 65%，画的东西反而少了**。

### 车手和车辆：矢量现画，不烤贴图

全部在一个「宽 100、脚踩 `y=0`、头朝 `-y`」的单位空间里描出来，贴到画面上只是一次 `translate + scale`。

**为什么不用贴图。** 一辆车在屏幕上占 8px 时，贴图只能"采样"：源图七十几列要塞进 8 个像素格，挑中哪几列全看四舍五入 —— 一辆橙色巴士可能整个采成挡风玻璃的深蓝色，而且距离每帧在变，远处的车会一路闪烁变色。矢量是**按图形覆盖率算**的，同样 8px 能画出车顶弧线、挡风玻璃的斜边和两只灯的位置。所以 mipmap、最小尺寸下限这些补丁全都不需要了。

顺带省掉的：车手不再需要按倾角和动作烤十几张图。压车是绕轮胎触地点 `rotate` 一下，踹腿、抡棍、被打、翻滚都是同一个函数里的分支。

两条画面上的规矩：

- **描边随距离退场**：`ink = destW < 16*PX ? 0 : 1.35*PX/k`。近处一圈 1.35px 的深色描边把轮廓咬出来；小到十几像素时描边会盖掉形状本身，直接不描。
- **车架永远是深炭灰，车主的颜色只做一块面板**。车壳跟夹克同色的话，人和车会在后视图里糊成一整块 —— 这是实际画出来才发现的。

### 街景仍然是贴图

楼、霓虹、路灯、招牌、棕榈、烟囱、储罐、塔吊……一帧里有一两百个，矢量现画太贵。开局按当前赛道的主题现烤一批（白天和夜里是两套），运行时按距离缩放贴上去，开双线性。每个精灵自带 `ww`（在世界里有多宽），跟源图分辨率解耦。

### 远处的车怎么才看得清

对向车的接近速度是双方相加（约 17600 单位/秒），留给你反应的那两秒里，一辆车只有几个像素宽 —— 这是投影本身的性质。除了上面的矢量绘制，还有四样：

| | |
| --- | --- |
| **视野 76° 而不是 100°** | 远处一切放大 1.53 倍，而**玩家自己的大小、路面宽度完全不变** —— 因为 `PLAYER_Z` 正比于 `camDepth`，两处约掉了。零填充开销，性价比最高的一项 |
| **设备像素分辨率** | 不再有低分辨率缓冲，`PX = H/360` 是设计单位，描边、火花、震屏幅度都挂在它上面 |
| **车辆尺寸下限** | `softFloor(destW, MIN_CAR_W*PX)`：远大于下限时几乎不动，趋近 0 时停住。透视因此略有偏差，换来的是远处的车不会缩成一个点 |
| **视距 560 段 + 雾调稀到 0.72** | 见下 |

**视距是两件事的乘积**：几何上画多少段（`DRAW_DIST`），以及雾在多远处把它糊掉（`theme.fogN * FOG_SCALE`）。原来 340 段等于 4.7 秒，但雾在 2.5 秒处就已经不透了 —— 后面那两秒纯属白画。段数拉到 560、雾整体乘 0.72 之后：

| 赛道 | 改前 | 改后 |
| --- | --- | --- |
| 市中心 | 0.17km / 2.5s | 0.32km / 4.8s |
| 滨江大道 | 0.21km / 3.1s | 0.40km / 6.0s |
| 工业区 | 0.16km / 2.3s | 0.30km / 4.5s |

（"看得清"取雾浓度 0.75 处，秒数按顶速 14600 单位/秒算。五条街一律翻了一倍。）

代价由上面的色带合并抵掉了。另外远处的演员和街景现在也吃雾（`fogAlpha()`）：背景本来就是雾色，压透明度等价于混雾。指数取 1.7，让车比路面晚一步糊掉 —— 车是要看的，路只是背景。

收窄视野的连带影响：近处的东西也跟着放大一倍，所以 `OFF_BAND()` 里楼的站位一起往外挪了，否则两堵墙把整条街夹死、天都看不见。

### 弯道里躲得掉吗：相机要往弯里转

直线上看得远解决不了弯道 —— **急弯会把路面横着推出画面**。曲率累积让远处的路中心在屏幕上线性外移，而路宽按 `1/n` 收缩，所以路面会在某一段直接走出屏幕边缘，跟雾和视距都无关。实测最急的弯（曲率 8）只剩 44 段可见，顶速下 **0.6 秒**。

同时量了一下变道要多久（相邻车道间距 0.42）：

| | 改前 | 改后 |
| --- | --- | --- |
| 一次变道（改装怪物，满速） | 0.53s | **0.42s** |
| 横穿整条路 −0.72 → 0.28 | 1.18s | **0.88s** |

**0.6 秒可见 × 0.53 秒变道 = 躲不掉。** 不是难，是数学上不成立。三处一起改：

1. **相机往弯里转**（`Cam.look`）。取前方 60 段的平均曲率，把整幅画面朝弯里平移。平移量**跟深度无关**，所以是"转头看"而不是"把弯掰直"——路还是那么弯，只是弯心留在了画面里。代价是车会往弯外滑，`LOOK_MAX` 封在屏宽的 22%。
2. **高速端转向没那么钝**：`1.45 - sp*.5` → `1.62 - sp*.32`。低速几乎没变，满速多出三成横向权限。
3. **对向车从 87\~130km/h 降到 60\~100km/h**。相对接近速度是双方相加，对向车贡献了三分之一，城里也不该开那么快。

### 还是不跟手：慢的一半不在车上，在起舵和镜头上

改完还是"高速变向像在推船"。再量，发现 0.42s 里只有 0.34s 是车真的在横移，剩下 0.08s 花在**起舵斜坡**上 —— `P.steer` 用 `approach(…, 14)` 从 0 爬到 1，按下去的头一瞬间转向权限几乎是 0。躲车的动作又基本都是"正往左走，突然要往右"，这时候要先把舵从 −1 拉回 0 再推到 +1，斜坡走两遍，慢得最明显。

再加上**相机横向跟随只有 8**：车已经在动了，画面还没动，手感上那一下就是没了。

| | 上一轮 | 这一轮 |
| --- | --- | --- |
| 高速端衰减 | `1.62 - sp*.32` | `1.85 - sp*.12` |
| 速度项 | `.35 + sp*.85` | `.40 + sp*.88` |
| 起舵速率 | 14 | 26（反打 60） |
| 相机横跟 | 8 | 11 |
| 一次变道（改装怪物，满速） | 0.42s | **0.28s** |
| 横穿整条路 −0.72 → 0.28 | 0.88s | **0.61s** |

反打单独给 60（基本是瞬间回中），是因为它救的是最难受的那一下；同向起舵留 26，不然按键会变成开关、没有"压车"的过程。车身倾角跟随也从 10 提到 13。

### 换向还是不跟手：慢的不是车，是相机

改完还是"换向没反应"。这回把两边分开量，数就说话了：

| | |
| --- | --- |
| 按下反方向后，车真的开始往回走 | **0.03s** |
| 按下反方向后，画面开始往回滑 | **0.22s** |

车早就转了，画面还在往原方向滑五分之一秒 —— 手上感觉到的"不灵敏"全在这。

原因是 `approach(Cam.x, Player.x, rate)` 这种一阶跟随有个**正比于横向速度的稳态误差**：满速打满舵时相机落后玩家约 0.16 条路宽。换向时这 0.16 得先被"走完"，相机才可能反向。**调快跟随只是把它按比例缩小**，永远除不尽 —— 这是为什么上一轮把 8 提到 11 没解决问题。

修法是给相机加一项**速度前馈**，把稳态误差直接抵掉，再故意留一个**封顶**的横滑当手感：

```js
const vxLag = Player.vx / CAM_RATE;                       // 一阶跟随的稳态误差
const slide = clamp(vxLag, -CAM_SLIDE, CAM_SLIDE);        // 只留这么多当手感
Cam.x = approach(Cam.x, Player.x + vxLag - slide, CAM_RATE, dt);
```

稳态下相机落后玩家正好 `CAM_SLIDE`，**跟速度无关**（原来是低速几乎不滑、满速滑 0.16）；换向时 `Player.vx` 一翻号，目标点立刻跳到相机另一侧，画面当帧就反。`Player.vx` 只取"我想往哪打"的那部分，离心力不算 —— 弯里镜头该往弯里转（那是 `Cam.look` 的事），不该被甩出去的分量带跑。

| | 改前 | 改后 |
| --- | --- | --- |
| 反打后画面开始反向 | 0.22s | **0.05s**（三帧） |
| 满速横滑 | 0.16（低速几乎不滑） | 0.08（封顶，各速度一致） |

`CAM_SLIDE` 是这里唯一要手调的东西：它既是画面上车能左右滑多远，也直接决定反打要几帧才见效（相机得先滑过这段距离才反向）。0.05 给两帧但画面偏钉，0.08 给三帧、滑感回来了，0.12 往上就开始重新有"打了没反应"的味道。现在取 **0.08**。

台架加了一条 `反打之后画面立刻跟着反`，卡在 0.06s —— 以后谁再动相机跟随或者把 `CAM_SLIDE` 调大，这条会先红。

量的是同一个东西：**一辆对向车第一次出现在屏幕上时，离撞上还剩几秒**（五条街、顶速、各 90 秒）：

| | 改前 | 改后 |
| --- | --- | --- |
| 最险的一次 | 0.48s | **0.55s** |
| 不到 0.8 秒的次数 | 10 / 262 | **3 / 246** |
| 中位数 | 3.5\~5.0s | 4.5\~5.4s |

中位数一直是四五秒，问题从来只在尾巴上。`playtest.js` 的台架里钉了两条：**最险的一次也要够变一次道**，以及**来不及躲的不到 6%**。把三处改动退回去，这两条会同时红。

### 护墙：一长条，不是一格一格拼

盘山的护栏和高架的防撞墙沿路是连续的。拿精灵一段一段摆，一侧就是几百次 `drawImage`，远处还会看出一片一片的缝。现在每一侧沿路收一串点（`renderWalls()`）：底边近→远、顶边远→近围成一个多边形，按雾分四档各填一次；护栏再加一条近处的立柱路径和一道高光。

**被坡顶挡住的部分怎么办？** 路面是由近及远画的，每一段都记着"比它近的路面最高挡到屏幕哪一行"（`seg.clip`）。那是一条水平线，所以把每个点的 y 压到不低于这一行，就是精确的裁剪 —— 整段藏在坡后的墙会被压成零高度，自然不画。

画在路面之后、街景和车之前。远处的车在弯里被近处墙挡住的那种情形会画反，但墙只有车一半高，弯道外侧的远车又在地平线附近，量出来基本碰不上。

### 雨

一条路径描完 130 根雨丝。每根的位置由序号散列出来、随时间往下落，不存任何状态，暂停时自然停住；斜度跟着车的横向速度和相机转头走。闪电是整片天刷一层亮色（天际线反倒成了剪影），外加一下很淡的闪白，雷声随机晚 0.3~1.4 秒。

### 镜头抖动：要"弹一下"，不要"信号不良"

**屏幕震**用两个不同频率的衰减正弦，不用 `Math.random()`。白噪声每帧独立跳，看着像画面坏了；正弦相邻帧连续，读出来才是"撞了一下"。`shake()` 还会挡掉比现有残量弱的新抖动，否则连续小碰撞会不断把相位重置成满幅、永远停不下来。

**落地抖动按落差给量**（`onLand()`）。原来只要腾空超过 0.14 秒就一律满幅震一次 —— 顶速碾过起伏路时一秒能弹好几次，画面一路在震。现在小跳给小反馈。

**镜头俯冲**（`Cam.dip`）原来是"离地就跳 6px、落地就跳回来"的硬开关，高速下前轮反复离地，整块画面跟着上下弹。改成渐变过去，并且要腾空满 0.1 秒才算数。

**紧张感是这几样一起给的**：命中冻结 60–85ms 的顿帧、屏幕震、径向速度线随速度变密、血少了画面边缘暗红脉动、引擎声跟着转速一挡一挡爬、风噪随速度开滤波器、对向车的喇叭带多普勒。

## 无头测试

```bash
node tools/test.js       # 跑完 fuzz + playtest（看退出码，不要看输出里有没有 ✗）
node tools/playtest.js   # 机器人跑完整生涯（含台架测试）
node tools/fuzz.js 60    # 随机输入 + 边角情况
node tools/shot.js       # 把八条街各画一帧存进 shots/（--only=5,6,7 只画这几条）
node tools/shot.js --vec # 把所有矢量图形按几档尺寸摊开，外加一排缩到 4px 的阶梯
node tools/shot.js --jitter  # 顶速下的画面稳定性：相邻帧逐像素差（直道、弯道各钉一处）
node tools/shot.js --corner  # 把车钉在每条街最弯的地方画一帧：能看见多少路、相机转了多少
node tools/shot.js --cost    # 路面这一层（含护墙）每帧画了多少条路径、多少个落点
```

三个跑测试的工具都**固定了随机源**（`seedRandom()`，默认种子 20260829，可以 `--seed=7` 换）。不播种的话同一份代码两次能跑出差好几位的名次，"失败"既可能是真回归也可能是手气差 —— 那种断言等于没有。

三个工具文件：

- `tools/env.js` —— 便宜的假 DOM + 打桩画布，只跑逻辑，用于 fuzz / playtest
- `tools/raster.js` —— 带抗锯齿的软件光栅化器：按覆盖率的多边形填充、描边加粗、双线性采样
- `tools/ctx2d.js` —— 架在上面的假 `CanvasRenderingContext2D`：变换栈、路径、贝塞尔、渐变、矩形裁剪

- **playtest** 让一个只会"压油门、躲车、见人就踹"的机器人从零开始跑完五场、中间买车。它比真人笨得多，所以它的成绩是**难度下限**：机器人场场垫底说明 AI 太快，场场通吃说明太松。后面的**台架测试**把战斗、掉武器、摔车重骑、警察抓捕单独架起来量，不受机器人水平影响。
- 台架里还钉了这次加的东西：对手出手前有 ≥0.30 秒前摇、看见蓄力闪开会打空、蓄力时先踹能打断；撂倒、擦车、贴尾流都能充氮气，放了能冲过极速、烧完回落；对手高速撞路障会翻；存档读得回、坏档会被纠正；经济进度没有车速墙。
- 八条街那一轮加的：有护墙的街冲不出去、贴墙掉血掉速；把人踹到墙上比路中间多掉 `WALL_SLAM`、僵直更久；油污和积水会打滑但不摔、手不动车也会溜、对手也会滑；两个头目比同场所有人都耐打都快、亲手撂倒才给赏金；四档难度的对手极速/血量/出手意愿/车流一档比一档高，蓄力一档比一档短，老手等于原来的数值；疯子通关解锁亡命、中途用过低难度不解锁；老版本存档读得进；四档难度的经济检查；新手和亡命的机器人名次拉得开。躲车那两条改用最快也最难拐的超跑，八条街都量。
- 台架开头会把车换回街车：原来它隐含依赖"生涯跑完手上是哪台车"，生涯变长、结束时车更快，警察那条就会因为玩家一头扎进对手堆里被围殴下车而挂掉。
- **fuzz** 灌随机输入和忽长忽短的 `dt`，连渲染一起跑，查异常、NaN、对象堆积，外加几个边角：起跑前狂点攻击、一直刹车、死命外压、终点前摔车、比赛中途重开。
- **shot** 顶掉假画布把**真正的一帧**画出来存成 PNG。前两个只能证明"不炸"，这个能证明"画得对" —— 地平线在哪、路面收没收敛、描边粗细对不对、远处那辆车还剩几个像素，出来一张图就看见了。转矢量之后这个尤其要紧：亚像素的东西该变成半透明而不是消失或者锯齿，只有真渲一遍才知道。`--vec` 把所有矢量图形摊开，最后一排是同一辆车缩到 4px→76px 的阶梯 —— 「车壳跟夹克同色会糊成一坨」就是在这张图上看出来的。
