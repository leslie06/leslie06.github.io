# Online: feedback, players online

Moved verbatim from CLAUDE.md on 2026-10-13. Dated entries say when and why (the user's words in 「」).

- Players' feedback (2026-10-11, 「做个用户可以反馈的功能」): the title and pause screens have 意见反馈 (`#feedback`, `ui/Feedback.ts` `FeedbackPanel`): a kind (bug / idea / praise / other), the text (2000), a contact if they want a reply, and the frame on screen when they opened it, ticked by default with a thumbnail (`FeedbackApi.capture`: `renderFrame` wrapped for one call, the drawing buffer read straight after, JPEG 0.72 at most 960 px wide - the engine keeps rendering while paused). `online/Feedback.ts` (system `feedback`, every world) sends `POST /fb` to the site's stats service (`statsEndpoint()` in Leaderboard.ts, shared: the published game sends, a dev server and shot mode not unless `?lb=<base url>`), with the game's side: build (the bundle's hash), quality, frame rate, device, screen, language, position and the nearest named road, driving or on foot, stars, the game's hour, seconds played; what cannot be sent waits in `drivecity.fb.pending` (4 at most, screenshots dropped first if storage is full) and goes 8 s into the next start. Server: `../stats/worker.js` (`fb` and `fb_shot` tables in `schema.sql`, 20 a device a day, the same text within 10 min once, no IP kept; read at `/fb?k=key`, linked from the dashboard; `node ../stats/test.mjs` covers it; `server.mjs` caps a body at 1 MB). Live since 2026-10-11 (the server's code had stayed at 2026-09-16, so that update also put the leaderboards live for the first time; the old code and database are in `/root/stats-backup-20261011-222223/` on the server). After changing `../stats`, copy `worker.js`, `server.mjs` and `schema.sql` up and restart (`../stats/README.md`) - committing is not deploying. Probes: `node .scratch/feedback/probe.mjs outDir [statsBase] [phone]` (sends from the title and the pause screen in the real loop; a local server: `(cd ../stats && DB_FILE=/tmp/fb.sqlite node server.mjs)`), `queue.mjs dbFile` (sends with the server down, starts it, reloads: delivered), `pageshot.mjs out.png` (the list page).
- Players online (2026-10-11, 「添加在线玩家人数」): the title and pause screens show 「当前在线 N 人 · 今天 M 人玩过」 (`Menu.setOnline`, a green dot), and in game a pill 「● N 人在线」 beside the radar's top edge (`Minimap` `.online`, reads `PresenceApi.online`; smaller with `dc-touch`). `online/Presence.ts` (system `presence`; only where `statsEndpoint()` is on) asks `GET /online?g=bcity` at the start, every 30 s of wall-clock time while a menu is up (systems get dt = 0 while paused) and every minute while playing. The server (`../stats/worker.js`) counts the sessions whose stats heartbeat (the snippet `stats/apply.mjs` puts in the deployed index.html, every 15 s; a background tab is throttled to a minute and drops out) came within `ONLINE_MS` 45 s - the `ev.seen` column, added to old databases by `server.mjs` with its index `ev_seen` - and today's devices; the game shows at least 1 (the page asking). A dev server has no heartbeat snippet. Probes: `node .scratch/feedback/online.mjs outDir [statsBase]` (fake heartbeats to a local server, reads the title and the pause screen's line), `online-radar.mjs outPrefix [statsBase] [phone]` (the pill in game) - never point the fake-heartbeat probes at the live server.
